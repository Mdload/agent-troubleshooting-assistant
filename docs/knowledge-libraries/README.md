## 检索约束

`knowledge_catalog.py`读取`planning/knowledge-libraries.json`。现有片段保留原编号、来源和日期，并加上`knowledge_libraries`、`device_types`、`deployment_environments`、`software_versions`、`version_status`和`source_scope`。

- 分区、设备类型、主备角色、运行模式、部署环境和软件版本是不同维度。六条传输链路不证明有六张SIM，三条PPP不证明是三卡设备。
- 明确问六卡/三卡、云/物理局端或软件版本时，先过滤候选，再BM25排序。版本未登记的具体配置不会代答明确版本的问题。无专属资料时如实显示缺项，可补充适用的通用原理。
- 共享章节由同一原始资料统一生成到相关模块；检索编号只建一次索引，避免重复命中。比较两类设备时允许两个范围，来源仍保留各自标签。
- 模型改写检索词后，宿主仍按原问题及相关追问限定资料范围；新分区不扩大设备工具或审批权限。
- `/api/knowledge-libraries`与网页侧栏“知识库”提供只读目录和整本模块阅读。计划主题、目录存在、离线测试通过均不代表设备知识已收录或当前状态已验证。

## 后续收录

先核实一台代表设备，整理脱敏资料并保留来源、采集日期和适用软件版本；沿`knowledge.py`的原始章节登记方式添加固定ID，并在清单的`record_metadata`中登记设备类型、分区、部署环境和版本。执行`python -B scripts/rebuild_knowledge.py`统一更新各模块；已审核发布的网页经验由程序动态合入，撤回/来源失效后移除。放文件进目录不会自动成为可信知识。

混合多类设备的章节应先按对象拆成独立片段，不能把整章统一标成三卡或六卡。软件版本使用`v2.4`一类明确标签；文件路径中的`croc2.0`或文档日期本身不能证明运行版本。

现有资料未确定设备类型、部署环境与软件版本，相关标签保持空值并标为`unconfirmed`。通用基础标为`public_principle`，其空标签表示原理不限制设备，不证明实验室所有设备都经过验证。现场原文和凭据不会在这一步自动外发。

这一版仍是BM25检索，没有引入向量数据库，也没有部署到62/140。
